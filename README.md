# Frameinsight Annotator

Local video annotation for person detection and tracking. Draw boxes, keep consistent person IDs, and correct editable interpolation between keyframes. Manual annotation works offline without a GPU or model downloads.

## Current workflow

1. Open the video library and choose **New video**.
2. Enter your class names, upload a video, and wait for preparation.
3. Press **N** and draw a box. Press **I** to assign/reuse a person ID, class, and color.
4. Move forward and adjust the same person's box. Auto-interpolation fills eligible frames between keyframes; inspect and correct the results.
5. Use hide/focus controls for overlapping people. Mark gaps when someone disappears and resume their track when they return.
6. Changes save automatically; **Save** and **Ctrl+S** are also available.
7. Click **Finish**, confirm your annotation coverage, and download annotation-only JSON or a native project backup.

The simplified editor uses one box per observation. Historical paired full/visible geometry and legacy conversion helpers remain in the code for compatibility. Direction arrows and future movement prediction are proposed work, not implemented features.

## Run locally

Prerequisites: Python with `venv`/pip and Node.js/npm. The application has been tested with Python 3.13 and Node.js 20.

```bash
./scripts/setup.sh
./scripts/start.sh
# Open http://127.0.0.1:8765
```

On Linux, `./scripts/start-background.sh` runs a user systemd service; `./scripts/stop.sh` stops it. The server binds to localhost. Network deployment and multi-user authentication are not part of this release.

## Data

Runtime data defaults to `.frameinsight/`: SQLite annotations, imported video copies, decoded frame caches, and exports. `FRAMEINSIGHT_DATA`, `FRAMEINSIGHT_WORKSPACE`, and `FRAMEINSIGHT_MODELS` override the corresponding locations.

Annotation JSON contains no embedded video or images. Keep original videos separately. The app restores native ZIP backups; direct custom-JSON import is future work. Lossless frame caching can consume considerably more disk than the source video.

Source control excludes footage, annotation databases, local backups, model weights, generated reports, and installer binaries. The synthetic browser-test video is generated by `scripts/make_fixture.py`.

## Tests

```bash
.venv/bin/python scripts/make_fixture.py
.venv/bin/python -m pytest tests -q
npm --prefix frontend test
npm --prefix frontend run build
```

Browser tests require the backend at `127.0.0.1:8765` and Google Chrome:

```bash
npm --prefix frontend run test:e2e -- editor.spec.ts
```

Use a separate `FRAMEINSIGHT_DATA` directory for the test server: browser tests create synthetic projects in whichever server they target. The optional real-video performance test needs locally supplied footage and is not a clean-checkout acceptance test.

The v1.2.0 verification passed 34 backend tests, 18 frontend unit tests, and 8 editor browser tests, plus manual Chrome checks. Windows packaging was tested under Wine; native Windows 10/11 validation remains outstanding.

## Windows packaging

The source includes a per-user Windows installer with an embedded runtime. Linux builds require Docker and the normal development setup:

```bash
./packaging/windows/build.sh
```

Generated installers appear in `deliverables/windows/` and are excluded from Git. Build dependencies and runtime archives are downloaded during packaging; the installed manual editor does not need those development tools. See [Windows instructions](docs/WINDOWS.md) and [third-party notices](packaging/windows/THIRD-PARTY.txt).
