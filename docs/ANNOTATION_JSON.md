# Custom annotation JSON v1

Choose **Export → Custom annotations JSON · no videos or images → Prepare export → Download annotations (.json)**. This is now the default export. The download is one UTF-8 JSON text file, not a ZIP and not a video. No PNGs, thumbnails, video data, base64 media, model weights or crops are included. `include_videos` is ignored for this format even when supplied through the API.

Export captures all saved annotations from all videos in the selected project, at one consistent database snapshot. It does not require numeric display IDs, individual approvals or whole-frame completion. A single-person track, incomplete annotations, unknown values and gaps are all preserved. Unannotated people are not falsely declared absent. Current unsaved browser edits must finish saving first.

## Document sections

| Field | Contents |
|---|---|
| `format`, `schema_version` | `frameinsight.annotations`, version `1` |
| `exported_at`, `media_included` | Export UTC time, always `false` for media |
| `project` | Project ID, name, creation time and exact saved revision |
| `conventions` | Class, coordinate axes/units, frame numbering, time units, null/gap meanings, scope and review semantics |
| `summary` | Video/person/observation/visible-box counts, available frame count, whole-frame checks and operation count |
| `videos` | Original names, dimensions, nominal FPS, source hashes, stored source references, indexing status and other saved video metadata |
| `frames` | Exact available source-frame ledger for each video: frame index, PTS, time-base numerator/denominator, seconds, codec key-frame flag and decode status |
| `annotation_index` | Convenience list ordered by video/frame/person: IDs, source timestamp, class, xyxy and xywh boxes, manual/interpolated origin, correction and anchor status |
| `state` | Complete original saved annotation entities; details below |
| `operations` | Ordered full edit history: before/after values, operation IDs, revision, server timestamp and undo/redo compensation links |
| `restored_history` | Historical records carried through earlier native imports, or `null` |
| `detector` | Cached suggestion coordinates/confidence/class, processed-frame records (including passes with no detections), detector settings/job records |

`state` contains `identities`, `segments`, `observations`, `intervals`, `links`, `reviews` and `proposal_reviews`, each keyed by permanent internal ID. Observations retain exact visible rectangles, identity/segment membership, optional occlusion/truncation, evidence notes, provenance, correction flags and historical review states. Older full-extent fields are retained if they were saved; no new full-body class or inferred geometry is generated by export. Unaccepted suggestions are separate from annotations.

## Reading a box

```json
{
  "observation_id": "example-observation",
  "video_id": "example-video",
  "frame_index": 6,
  "timestamp_seconds": 0.2,
  "identity_uuid": "example-person",
  "person_id": 1,
  "class_name": "person_visible",
  "box_xyxy": [100.0, 80.0, 200.0, 300.0],
  "box_xywh": [100.0, 80.0, 100.0, 220.0],
  "annotation_type": "keyframe",
  "origin": "interpolated",
  "human_corrected": true,
  "protected_from_interpolation": true
}
```

This example is a generated box that a person corrected; it is now a protected annotation keyframe. `annotation_type` can be `keyframe`, `interpolated` or `missing_box`. `origin` separately retains `manual`, `copied`, `model`, `interpolated`, or null when not recorded. Geometry is in unrounded original-image pixels, not screen coordinates or normalized fractions. A null box is not a positive label. `frames[].key_frame` is a video-codec property, not an annotation keyframe.

Frame numbers start at zero. Timestamps come from the actual source ledger, not frame/FPS estimates; unavailable timestamps remain null. Intervals include both endpoints; a null end is still open. An absent observation now produces a derived `not_visible` label under the no-box visibility policy; it is not proof of physical absence or completed review. Explicit gap intervals record complete invisibility and its reason. Null occlusion/truncation values mean unspecified, not false. Historical `draft` flags are retained without adding a per-person approval requirement.

## Media, portability and limits

Keep source videos separately. Their filenames and SHA-256 hashes let you match annotation coordinates to the correct footage without putting footage into the export. Source filesystem paths are informational metadata, not embedded files. Export does not delete the original videos or local frame cache the editor needs.

The JSON can be read directly by other tools. The app's current restore dialog accepts native ZIP archives, not this custom JSON; direct JSON re-import is not yet implemented. No claims of individual annotator identity, object visibility percentage, or unrecorded timestamps are invented. Full recorded history makes this file larger than a minimal list of boxes, but it contains no media.


The video-first interface opens downloads through **Finish**. Its JSON export
is scoped to the selected video (`video_scope`). The saved class catalog is
in `classes`; person labels and colors remain in identities and the annotation
index. For a scoped export, edit-history changes are filtered to that video's
entities; cross-video restored history is omitted. Native project backups
retain the complete project and full replayable history. Finishing records the
user's confirmation and revision in video metadata without inventing frame reviews.

## Automatic visibility

`visibility_intervals` covers every source frame for each person associated with
that video, using compact inclusive runs rather than repeating empty boxes:

- `status`: `visible` when a box is present, otherwise `not_visible`.
- `basis`: `box_present`, `no_box`, or `explicit_gap`.
- `reason`: null for visible boxes, `unknown` for automatically missing/deleted
  boxes, or a previously recorded explicit cause such as `occlusion` or `outside`.
- `video_id`, `identity_uuid`, `person_id`, `start`, and `end` identify the run.

No-box runs include frames before the first appearance and after the last.
These are derived annotation labels, not proof of physical occlusion or exhaustive
human review. They update automatically when boxes are added, removed, or
interpolated. Eye/Focus do not alter them.

Delete (one frame) and Delete boxes in range also store an explicit interval
with reason `unknown`, preventing interpolation from restoring deleted boxes.
Drawing inside that interval restores the drawn frame and trims/splits the
interval automatically. Undo restores the boxes, segments, gaps, and review
states together. `annotation_index` also includes a `visibility` field; empty
frames without observations are represented by `visibility_intervals`.
