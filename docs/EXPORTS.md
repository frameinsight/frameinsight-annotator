# Export and interchange

The default **Custom annotations JSON** is a single media-free `.json` file containing the complete saved annotation state, source-frame ledger, provenance, gaps, identities, notes, detector records and timestamped operation history. It takes a consistent SQLite snapshot and has no completeness gate. See [schema and field guide](ANNOTATION_JSON.md).

Other exports are immutable ZIP snapshots of a server-acknowledged project revision. Each ZIP profile includes `native/project.json`, export settings, a manifest and exclusions. Export jobs have explicit queued/running/completed/failed states and download links in the export dialog.

**Native:** schema version 1 contains identities, paired observations, source hashes and frame timestamps, segments, intervals, identity links, provenance, review states, proposals and operation history. Include videos for a portable archive. Restore validates exact source hashes and decoded ledgers. A source reference alone requires that exact source to remain available locally.

**CVAT video XML:** the current export contains only `person_visible` tracks, with fixed `person_id` and internal identity. Historical full-body boxes remain in the native sidecar. The underlying dual-format helper is retained for compatibility. Track IDs are independent of person IDs. Per-frame keyframes and outside markers terminate unavailable geometry spans. The visible track carries full-quality metadata so unknown A survives. Native sidecars preserve richer gaps and decision history. Numeric IDs are required. Import uses defused XML parsing, exact explicit frame indices and explicit person_id attributes. Ambiguous pairing is rejected; missing identity attributes become unpaired provisional drafts. External sparse CVAT tracks are imported at their explicit keyframes only; interpolation is not silently materialized. The earlier dual-box A/B XML round-trip passed through the local CVAT 2.75.0 server for the completed real clip: 96 tracks, 7,937 positive boxes, 106 outside markers and all attributes. Maximum rounding error was below 0.005 source pixels. See `cvat-server-roundtrip.json`; other server versions still need their own checks.

**YOLO:** the current UI exposes only `visible_only`: one class, `person_visible` (class 0). Optional occlusion/truncation flags and missing A do not block a reviewed visible image. A whole-frame check accepts valid visible geometry without individual person approvals; interpolated and manual boxes are both eligible. Legacy API profiles remain available for compatibility: `dual_class` uses class 0=A, class 1=B; equal coordinates are retained as distinct classes. `full_only` uses class 0=A; `visible_only` uses class 0=B. Center/size coordinates have nine decimal places; coordinate round-trip tolerance is 1e−5 pixels for the 640-pixel fixture. The archive includes lossless source-frame PNGs, labels, class mapping YAML, pair mapping, frame timing and exclusion reports. Only reviewed-complete images enter the dataset. Unknown A excludes the **whole image** from full/dual profiles. Empty reviewed frames get empty label files. Entire project groups are assigned to a single train/val/test split; combine independent recording groups to supply other splits. Adjacent frames are never randomly split. YOLO text itself does not represent pairing.

**MOT:** the explicitly selected `motchallenge-1based-unknown-visibility` profile exports exactly one visible geometry per verified numeric identity in the current UI. It requires every frame in the continuous clip to be reviewed-complete. Frame numbering and xy origin are 1-based; width and height use source pixels; mark/confidence=1; pedestrian class=1; visibility=−1 means unavailable. No area ratio or occlusion-derived fraction is invented. The archive contains images, gt.txt, seqinfo.ini and original timestamps. This profile is only appropriate for evaluators that accept unavailable visibility. External evaluator validation is not claimed. Unsupported unknown geometry/identity returns an actionable job error.

Original images are never shifted because panels or browser zoom changed. Converted outputs are derived views, not replacements for native state. ReID crop generation and model training are outside this release.
