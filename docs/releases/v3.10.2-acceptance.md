# 3.10.2 verification

Updater tests cover one automatic check per managed app process, verified downloads, startup mutation protection, offline/current/error recovery, repeated-launch loop prevention, source-checkout isolation, and the detached installer arguments. Debian handoff tests cover successful installation, declined authorization and incorrect installed versions; only a successful verified install reopens the app.

Chrome acceptance covers automatic startup progress without update-button clicks, protected startup dialogs, browser reconnection after installation, and returning to annotation after a failed update. Existing manual update, download, cache and save-flush tests remain in place.

The release workflow requires all frontend/backend/browser tests and native installed-package tests before publication. Windows acceptance invokes the real detached system PowerShell helper from the installed Python runtime, silently reinstalls, verifies the version, reopens and stops the app, then checks unchanged annotation data. Debian acceptance uses the real frozen helper and apt in a disposable container; only administrator authorization is substituted. It verifies automatic reopening and unchanged database bytes.

Physical Windows 10/11 desktop interaction and a real desktop authorization dialog are not claimed. The first upgrade from a pre-3.10.2 version still uses its existing manual update flow. Administrators and isolated tests can set `FRAMEINSIGHT_DISABLE_AUTO_UPDATE=1`; development checkouts never install automatically.

Local verification passed all 235 backend tests, all 122 frontend tests, the production build, and all eight updater browser cases. The installed Debian container passed 31 runtime, automatic update, restart, data-preservation and removal checks.

The full local Chrome suite passed 59 cases, with one optional real-user-video measurement skipped in isolated test data.

The initial 3.10.0 candidate was not published because the native Windows handoff failed. This candidate starts system PowerShell with a valid hidden console, initializes its module paths independently of the parent shell, and records installer startup diagnostics. The release remains gated on native Windows installation and reopening.

The focused native Windows handoff test passed on Windows Server 2022: a checksum-verified official installer silently reinstalled and the desktop app reopened at the expected version. Evidence: https://github.com/frameinsight/frameinsight-annotator/actions/runs/37460041317. Full installed-package acceptance is rerun against the final 3.10.2 binaries before publication.

The installed Windows acceptance shuts down through the desktop launcher (WM_CLOSE), matching the real update service, before checking database preservation and uninstall. Signaling the server event alone would incorrectly trigger the launcher’s unexpected-exit dialog.
