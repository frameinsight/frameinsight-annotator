# 3.11.4 verification

All mutation checks use isolated disposable projects. No user annotation project was changed.

## Large multi-camera import

A generated 210.60 MiB version-1 session JSON contains 12 cameras, 72,000 source frames, 71,280 observations and 141,840 boxes across two named classes. Its editable state is 52.87 MiB; repeated export listings and frame ledgers make up the rest. The previous parser rejects this file with the reported “Camera session state exceeds 128 MiB” error.

The corrected parser and structural preview accept the same file. Full import succeeds, followed by exhaustive comparison of all 71,280 observations' geometry and provenance. Local IDs, shared person ID 17, class names/colors, camera offsets and all presence intervals are preserved. All 36 pre-existing destination entities remain unchanged. The import records batches of 49,000 and 22,376 changes in one transaction, ending at project revision 2.

On the development machine, structural preview took 47.34 seconds and import took 69.90 seconds, with peak process memory of about 525 MiB and 812 MiB respectively. These measurements are for the synthetic fixture, not a promise of speed on other hardware. The reporter's original 200 MB file was not supplied.

A manual in-app browser check also uploads this 210.60 MiB fixture and reaches the camera matching list without the old error. Screenshot: `.frameinsight/qa/large-session-3.11.4/manual-camera-preview.png`. Local before/after fixture scripts and measurements are under `.frameinsight/qa/large-session-3.11.4/`.

## Regression checks

The production frontend build, 163 frontend tests and 347 backend tests pass. Backend tests cover duplicate keys and malformed skipped history, gzip/BOM input, editable-state/row/decompression limits, temporary-file cleanup, projection tampering, exact source matching, bounded batch revisions and rollback after a final session-write failure. Single-video import limits and existing native import behavior are unchanged.

Four new Chrome tests pass: import error placement and file reset; preview while videos prepare with distinct ready mappings; import progress/error retry; and real export/download/UI-import roundtrip preserving boxes, local IDs and shared assignments.

The 14 existing multi-camera browser tests and four existing project/import browser tests also pass. One initial upload test stalled because the fresh local QA environment lacked the packaged `websockets` dependency; installing the already-pinned dependency and restarting that test server resolved it without application changes. An independent review found no actionable regression and passed 200 randomized nested-row equivalence/cleanup probes.

The full 210.60 MiB multipart HTTP preview also returns HTTP 200 with all cameras and box counts intact. No source media or user data is included in the regression fixture.
