# Frameinsight 3.11.4

## Reopen large multi-camera sessions

- Fix multi-camera annotation imports failing with “Camera session state exceeds 128 MiB” when repeated export listings and frame ledgers push a file over that internal limit. Large row collections are read through temporary disk storage, while current editable state remains bounded in memory. Existing session JSON and JSON.gz files remain supported.
- Preserve validation of source timestamps, box listings, local track IDs, shared identities and camera assignments. Original recordings still need to match the exported source hashes. Existing annotations are kept.
- Import larger sessions atomically using bounded operation batches, so a late validation or save failure cannot leave a partially imported session.
- Show import errors beside the selected JSON, indicate when the app is reading or importing, and explain when original videos are still preparing.

## Update

Save your work, fully exit Frameinsight through the tray icon, then reopen while online. Closing the browser alone does not stop the app. You can also install the Windows or Debian package over the existing installation.

Keep the original annotation JSON and videos. After updating, choose the same JSON again through **Multiple cameras → Import a multi-camera annotation JSON → Read camera list**. Match each camera to its original video once that video finishes preparing, then import. You do not need to annotate again or manually remove fields from the JSON.
