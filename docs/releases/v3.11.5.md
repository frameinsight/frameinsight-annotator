# Frameinsight 3.11.5

## Responsive multi-camera autosave

- Fix repeated save waits and stale “Still saving” errors during camera-session refreshes (#12). Routine session refreshes wait for annotation acknowledgements without forcing another save. Shared-person metadata can save while box corrections are pending; new track assignments still wait for the referenced track to be saved.
- Save browser recovery using periodic annotation checkpoints and individually stored operations. Repeated edits and server acknowledgements update a small journal instead of cloning every camera's boxes and the entire undo history. Existing full-snapshot recovery journals remain readable; pending edits, exact Undo/Redo and failed-save retries are preserved.
- Show annotation saves in the multi-camera save indicator so it cannot claim “Saved” while box updates remain pending. Explicit Save, Finish and project changes wait for actual completion or report an actual save failure.
- Keep live status updates independent of annotation volume by reading only project revisions and video metadata. Build all camera appearance strips in one annotation pass and group hidden intervals by track during backend validation.

## Update

Save your work, fully exit Frameinsight through the tray icon, then reopen while online. Closing only the browser does not stop the app. You can also install the Windows or Debian package over the existing installation. Confirm the app shows **LOCAL · 3.11.5**.

The report did not include crash logs, so a specific crash cause could not be confirmed. This release removes repeated large recovery copies and annotation reloads that caused avoidable processing and memory pressure. Please include the app version and diagnostic details if a crash recurs.
