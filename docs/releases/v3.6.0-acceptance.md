# 3.6.0 verification

Local Ubuntu verification before tagging:

- 186 backend tests passed.
- 111 frontend unit tests passed.
- All 52 applicable Chrome browser tests passed in one full run. One optional private-video performance benchmark was skipped.
- Production frontend build, release version consistency and diff whitespace checks passed. Dependency versions are unchanged.
- Unit coverage includes forward/backward replacement drawing, reopening without local undo history, repeated overlapping deletions, keeping newer gaps blocked, legacy projects without repair markers, rejected missing/reversed endpoints, and exact Undo/Redo.
- New browser regressions draw replacement boxes across a fresh browser session, preserve other class geometry and outside hidden frames, validate and export JSON, exercise Shift+K with a preview, and verify missing-endpoint errors and atomic undo. Existing deleted-box recovery tests also preserve current boundary corrections and recover original coordinates after reopening.
- Manually tested through computer use: previewed and filled an existing deleted section, undid the fill, then drew two new boxes inside a deleted interval. The intermediate frames became Present and outside deleted frames remained Hidden. Inspected the dialog layout.
- Tests used an isolated data directory. Existing local projects, videos, annotations, operation history and frame ledgers were backed up and verified unchanged after restarting the local app at 3.6.0.

The tagged release workflow repeats the full suite and gates publication on native Windows installer/runtime verification, Debian installed-runtime verification and source-license packaging. Successful releases include machine-readable verification reports alongside the installers.

Windows validation uses a native CI runner; Debian validation uses a headless container. This is not a physical Windows 11 laptop acceptance test.
