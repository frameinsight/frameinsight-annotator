# 3.7.0 verification

This release adds standalone temporal trimming and configurable JSON attachment names.

Local verification: production frontend build passed, 116 frontend tests passed and 204 backend tests passed; Chrome acceptance passed 54 tests, with one optional real-clip performance benchmark skipped.

- Backend regressions cover exact selected frame content and VFR timestamps, unchanged source files and project state, section union, inclusive boundaries, single-frame output, invalid ranges, queued cancellation, preserved audio, exact even/odd dimensions, pixel aspect ratio and display rotation. JSON tests cover safe portable filenames, default video naming, custom names and missing export errors.
- Frontend tests cover section normalization and invalid boundaries. Chrome acceptance drags section handles, prepares two sections, previews and downloads the MP4, reloads the preparation page and imports the result as a new annotation video. JSON acceptance downloads a custom filename and checks preflight error feedback.
- Manual computer-use acceptance on the isolated app opened Trim sections, uploaded the numbered fixture, dragged the end handle to frame 5, added frames 15–20, created the MP4 and played it through source frame 20. The player reported 640 × 360, matching the input. Original annotations were untouched.
- A reported failed user download returned HTTP 200 with a valid JSON attachment. Chrome reported an organization block. Browser security prevented policy-page inspection. This release does not remove that browser restriction or change security settings.

Publication is gated by the complete frontend/backend/Chrome suites, version checks, native Windows install/runtime/upgrade/uninstall checks, Debian installed-runtime/data-preservation checks and corresponding-source packaging. Platform verification reports accompany the release. Physical Windows 11 laptop interaction is not claimed.
